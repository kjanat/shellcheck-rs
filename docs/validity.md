# Validity matrix

The oracle proves the port equals upstream. The validity matrix proves a
diagnostic's claim by running its reproducer in real shells, one container per
shell and version.

## Pieces

| Path                                 | Holds                                                                   |
| ------------------------------------ | ----------------------------------------------------------------------- |
| [`validity/sources.toml`]            | The one hand-written input: per shell, how to fetch and which versions. |
| [`validity/matrix.toml`]             | Generated by `cargo validity pin`: every cell with its pins and digest. |
| [`validity/specs/SC<code>.toml`]     | One spec per diagnostic: snippet, fix, claim, observable.               |
| [`validity/outcomes.toml`]           | Generated by `cargo validity --record`: outcome per spec per cell.      |
| [`validity/REPORT.md`]               | Generated with the outcomes. Per code: where it reproduces, where not.  |
| [`dialect_rules.rs`]                 | Generated by `cargo validity rules` and `--record`: added-dialect rows. |
| [`docker/shells/<shell>/Dockerfile`] | Builds one interpreter from the pinned source. `fetch.sh` verifies it.  |
| [`schemas/`]                         | Generated by `cargo schemas`: one JSON Schema per file format.          |

## Schemas

`cargo schemas` writes `schemas/<name>.schema.json` from the Rust types that
read each format: `validity-sources`, `validity-matrix`, `validity-outcomes`,
`validity-spec`, `upstream-pin` for `tools/oracle.json`, `wasm-request` for the
WASM request and `json1-output` for `--format=json1`. Each TOML file names its
schema on a `#:schema` first line, and `tools/oracle.json` in its `$schema` key.
A drift test per schema in `crates/conformance/src/schemas.rs` fails when a
committed schema differs from what the types generate.

## Sources and pins

`sources.toml` names each shell once:

```toml
[shell.bash]
kind     = "tarball"
url      = "https://ftp.gnu.org/gnu/bash/bash-{version}.tar.gz"
versions = ["3.2.57", "5.3"]
argv     = ["bash"]
shipped  = true
dialect  = "bash"
```

`kind` is `tarball`, `git` or `crate`. A tarball pin is the URL and its
SHA-256. A git pin is the repository, the tag and the commit it resolved to.
A crate pin is the crates.io version. `cargo validity pin` resolves every
version, keeps pins already in `matrix.toml`, resolves the base image to a
digest, and asks the registry for each image's digest. `pin --refresh`
re-resolves git tags and base digests.

`cargo validity build [--push]` builds each cell from
`docker/shells/<shell>/Dockerfile` with the pin as build arguments.
`fetch.sh` in the image verifies the checksum or the commit before anything
compiles. `--push` pushes and writes the digest into `matrix.toml`.

## Cells

A cell in `matrix.toml`, as `pin` writes it:

```toml
[[cell]]
shell      = "zsh-sh"
version    = "5.9"
image      = "ghcr.io/kjanat/shellcheck-rs/shell-zsh:5.9"
digest     = "sha256:…"
base       = "debian@sha256:…"
dockerfile = "zsh"
argv       = ["zsh", "--emulate", "sh"]
parse      = ["-n"]
shipped    = false
dialect    = "sh"

[cell.source]
kind   = "tarball"
url    = "https://www.zsh.org/pub/zsh-5.9.tar.xz"
sha256 = "…"
```

`shipped` says whether the port has a `--shell` value for this cell. `dialect`
names the port shell the cell stands in for when checking the snippet. A cell
without `dialect` is checked as its own shell when the port has that `--shell`
value, and any other cell skips the port assertions. `vm = true` marks a cell
whose shell runs inside a guest operating system under QEMU; its source is
`kind = "image"`, a disk image URL with its SHA-256.

The generated report is the current inventory of shells and versions. Some
BSD shells run in guest operating systems because their native binaries do
not run on Linux. A shell with an unrelated grammar, such as tcsh, normally
records `unparsable` for POSIX shell specs.

## Specs

```toml
code  = 2086
claim = "an unquoted expansion word-splits and globs"

[snippet]
script = 'x="a b"; printf "<%s>" $x; echo'

[fixed]
script = 'x="a b"; printf "<%s>" "$x"; echo'

[observe]
kind    = "stdout"
snippet = "<a><b>\n"
fixed   = "<a b>\n"
```

`observe.kind` is one of `stdout`, `status`, `stderr-contains`, `parse`. A
spec may carry several `[[observe]]` blocks. Scripts read stdin and finish in
under a second.

A `parse` observe runs only the cell's parse step. Its values are `accepted`
or `rejected`. For process substitution, which sh rejects as syntax, the spec
writes `snippet = "rejected"` and `fixed = "accepted"`:

```toml
[[observe]]
kind    = "parse"
snippet = "rejected"
fixed   = "accepted"
```

Filesystem: the root is read-only and `/tmp` is a 16 MiB tmpfs. Each run gets
a fresh directory in `TMPDIR` and starts there. A spec that needs a missing
path uses `$TMPDIR/missing`; one that needs files creates them under
`$TMPDIR`. `cd` into a missing path fails without writing anything, so SC2164
style claims need no writes at all. Nothing outside `TMPDIR` is writable and
the directory is discarded after the run.

## Assertions per spec per cell

1. The shell parses the fixed script, and the snippet unless a `parse`
   observe expects its rejection.
2. The snippet produces `observe.snippet`.
3. The fixed script produces `observe.fixed`.
4. During verification, a recognized port dialect reports `code` on a
   reproducing snippet when the spec applies to that dialect's floor.
5. During verification, that dialect reports nothing with `code` on the fix.
   For an added dialect, an `absent` snippet must also be silent unless another
   version records `reproduces`. Upstream dialects preserve their portability
   diagnostics: one shell accepting an extension does not make it portable.

## Outcomes

| Outcome      | Meaning                                                              |
| ------------ | -------------------------------------------------------------------- |
| `reproduces` | Assertions 1 to 3 hold. The claim is true on this shell and version. |
| `absent`     | Both scripts produce the fixed observable. The shell lacks the bug.  |
| `differs`    | Some other output. Recorded verbatim.                                |
| `unparsable` | The shell rejects the fix, or the snippet without a `parse` observe. |
| `timeout`    | Exceeded the per-run limit.                                          |
| `port-miss`  | Assertion 4 or 5 failed.                                             |

`cargo validity` verifies current results against the committed outcomes.\
`cargo validity --record` records shell evidence without port assertions,
then updates those outcomes and `dialect_rules.rs`. Verification checks the
port against the generated rules; recording does not depend on the old rules.
Recording also removes rows for retired specs or cells. A partial recording
preserves other current rows and regenerates the report for all current specs.

## Gate

- During verification, a shipped cell's changed outcome fails. `port-miss`
  fails. Recording reports changed outcomes as drift.
- An unshipped cell: changes are reported, never fatal.
- A full-matrix run without `--record` fails on a row with no recorded
  outcome. A `--record` run and a `--cell` run report the row as new.
- A spec with no `reproduces` cell at all fails: the claim is false
  everywhere we can test, and the diagnostic needs rethinking.

## Rules

```sh
cargo validity rules
```

`rules` reads `outcomes.toml` and `matrix.toml` and writes
`crates/shellcheck-rs/src/dialect_rules.rs`: one `Rule` per
`(code, dialect, version, outcome)` for every row whose cell shell names a
dialect beyond upstream's five. Cells that name no dialect, such as `zsh-sh`
and `tcsh`, and cells of upstream shells are left out. A row whose cell is
missing from `matrix.toml` fails the command. Rows sort by code, dialect name
and version, so a second run writes the same bytes, and a test compares the
committed table with what the committed outcomes render. `cargo validity
--record` writes the table from the outcomes it records.

`crates/shellcheck-rs/src/dialect_policy.rs` reads the table. A dialect keeps
a code when it has no row for the code or any version records `reproduces`,
and drops it when every weighted row records `absent`. `differs`,
`unparsable`, `timeout` and `port-miss` rows carry no weight. Every cell runs
under its shell's default options. A script that runs `setopt`, `unsetopt`,
`emulate`, `eval`, `.`, `source`, `alias`, or `set` with an option flag keeps every code of its floor, also
behind a zsh precommand modifier such as `builtin`. So does a script whose
shebang passes the interpreter an option flag, as in `#!/bin/zsh -y` or
`#!/usr/bin/env -S zsh -y` (also `-Szsh -y`), or a zsh script that assigns to the special
`options` array, as in `options[shwordsplit]=on`.
Writes to zsh's `functions`, `aliases`, `galiases`, `saliases` or their `dis_`
variants also keep floor codes: their values can define commands that change options.
GNU `env -S` quoting, escapes and comments are decoded when identifying the
interpreter and checking its flags. Dynamic expansions or unsupported `env` arguments keep floor codes.
`Policy::of(dialect, root)` returns `Measured` for an added dialect whose
script keeps the default options, else `Floor`. The checker drops the analysis
findings whose code `Policy::keeps` rejects, after analysis and alongside the
`disable` directives. Upstream dialects never consult the table, so the
snapshot and the oracle gate do not move for them. The `added-dialect`
deviation class expects the port's findings to equal the oracle's run as the
floor shell minus the codes the policy drops.

Every dialect with a `--shell` value has `shipped = true` in `sources.toml`,
and the gate treats changes to its cells as fatal.

## Report

`REPORT.md` has one section per code:

```sh
## SC2086
Claim: an unquoted expansion word-splits and globs.
reproduces: bash 3.2–5.3, dash 0.5.8–0.5.12, ksh93 u+ 2020, busybox 1.30–1.37,
            zsh emulate-sh 5.9, mksh R59, yash 2.56, osh 0.24
absent:     zsh native 5.9
```

The report is generated from `outcomes.toml` and committed with it.

## Runner

```sh
cargo validity [--record] [--cell <shell>[:<version>]] [--code <n>]
```

The runner reuses one isolated container per cell. Scripts arrive on stdin
and have a five-second limit. Nothing is mounted; the network and Linux
capabilities are disabled; the filesystem is read-only except for a temporary
directory. The runner uses the image digest recorded in `matrix.toml`, then a
local build of the cell's tag if that digest is unavailable. A cell with
neither is recorded as `missing` and the run continues.

Parsing happens with the shell's `-n` first where the shell has one. For
`emulate-sh` cells the parse step runs the same argv with `-n` appended.

VM cells use a throwaway disk overlay and expose no guest network beyond the
runner's private command channel.

## Images

One Dockerfile per shell lives under `docker/shells/`. Published images include
GitHub build-provenance and SPDX SBOM attestations. The image name is
`ghcr.io/kjanat/shellcheck-rs/shell-<shell>:<version>`; the digest lands in
`matrix.toml`. Verify an image with:

```sh
gh attestation verify oci://ghcr.io/kjanat/shellcheck-rs/shell-bash:5.3 --owner kjanat
gh attestation verify oci://ghcr.io/kjanat/shellcheck-rs/shell-bash:5.3 --owner kjanat \
  --predicate-type https://spdx.dev/Document/v2.3
```

## Reproducibility

Every input is pinned in the tree and every step is one command.

- `matrix.toml` records each image by digest. The runner pulls by digest and
  falls back to a local build of the same cell only when the digest is
  unreachable. `cargo validity pin` clears the digest of a cell whose image
  the registry no longer has.
- `matrix.toml` pins each source tarball URL with its SHA-256, or each git tag
  with its commit. A rebuild from the same pin yields the same interpreter.
- `outcomes.toml` and `REPORT.md` are committed. A fresh checkout plus Docker
  reproduces them with `cargo validity --record` and `git diff` shows drift.
- The runner uses no host shell. A host without Docker fails the run with one
  message.
- Container clocks, locale and environment are fixed: `LC_ALL=C`, `TZ=UTC`,
  empty environment apart from `PATH`, `HOME=/tmp`.
- Spec execution order is sorted by code then cell. Output is deterministic
  byte for byte.

## Fuzz

Fuzz scripts are never executed. The matrix runs curated specs only. The
syntax-only pass is `cargo conformance-shells [--cell <shell>[:<version>]]
[--iterations <n>]`. It feeds the property corpus plus generated shell to each
cell's `argv` plus `parse` in the same container setup as the runner, and
compares the shell's verdict with the port's (checked as the cell's shell, or
as its `dialect` for an emulation cell) and with the oracle's (only for cells
with a `dialect`). It prints one line per cell, sorted by shell then version,
with `rejects-valid` and `accepts-invalid` counts for the port and the oracle.
A VM cell is skipped and says so; a cell without `dialect` says
`no upstream dialect`. The numbers are a report, never a gate.

## Relation to upstream

For floor cells the oracle's verdict on the snippet is recorded alongside,
as `oracle = "reports" | "silent"`. Where the port reports and the oracle
does not, the spec is the evidence a sanctioned deviation needs.
